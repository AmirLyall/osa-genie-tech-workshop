A hands-on hour for OSA's technical team on making a Genie Agent reliable. You'll build an agent from a set of P-card tables, score it with a set of worst-practice questions written the way people really ask, fix what fails at the right layer, and re-run the benchmark to prove the fixes worked.

Instructions, example queries, metric views and agent-level metadata. Each fixes a different kind of failure.

1 Kickoff

Goal: agree on what "good" means and how we'll measure it. 12:00 · 10 min

Users rarely ask the way a query is written. They use vague dates, shorthand only OSA would understand, and terms nobody has defined. Today's benchmark questions are written that way on purpose: worst practices. A well-tuned agent should still get them right, and you'll treat each miss the way you'd treat a failing test.

Worst practice: how people askBest practice: what they mean
Find fraud.Transactions made after the cardholder's termination date in fiscal year 2026.
Who are our big spenders?The top 10 cardholders by total spend in fiscal year 2026.
Which cards are dormant?Active cards with no purchases from April 1 to June 30, 2026.
How much did we spend last quarter?Total spend for fiscal year 2026 Q4, April to June 2026.

Business users were coached on the right-hand column last week. Your job is the other half: make the agent cope with the left-hand column, because that's how most people will ask.

Lower layers are more deterministic. Every piece of business logic should live as far down as possible.

Last option, least reliable

Text instructionsFast but optimistic

Text instructions: formatting, scope and clarification prompts. Great for fast iteration and subjective changes, but open to interpretation, and they can be ignored if the context gets overloaded.

SQL expressionsExample-based pattern matching for reliable outcomes

SQL expressions: Genie's strongest signal for writing queries. It learns from examples, which captures your team's expertise.

Unity Catalog metadataTable and column descriptions, synonyms, table context

Unity Catalog metadata: passive but important. It helps Genie pick the right tables and columns, and it helps everyone else who builds on Unity Catalog too.

Metric viewsEnforced semantic layer: calculations, joins, governed metrics

Metric views: enforced and deterministic. Calculations always run exactly as defined. You can add synonyms for KPIs, so Genie learns your business terms.

Preferred, most reliable

Today's flow

  1. Create a bare agent from the six tables.
  2. Load 10 worst-practice benchmark questions, each with a reference SQL answer.
  3. Run the benchmark and record your baseline score.
  4. Fix the failures, choosing the lowest layer that works.
  5. Re-run the benchmark and compare.
How a benchmark scores. For each question, Genie answers as it would for a user, and its result is compared with the result of your reference SQL. The run reports an accuracy score, and you can open any question to compare Genie's output with the ground truth.

The 10 benchmark questions

The SQL uses the catalog from your settings. Each reference answer was checked against the workshop tables.

Question 1

How much did we spend last quarter?

SELECT ROUND(SUM(amount), 2) AS total_spend
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions
WHERE fiscal_year = 2026 AND fiscal_quarter = 'Q4'

Question 2

Which agencies have bad receipt compliance?

SELECT a.agency_code, a.agency_name,
       ROUND(100 * AVG(CASE WHEN t.receipt_attached THEN 1 ELSE 0 END), 1) AS receipt_compliance_pct
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.agencies a ON t.agency_code = a.agency_code
WHERE t.fiscal_year = 2026
GROUP BY a.agency_code, a.agency_name
HAVING ROUND(100 * AVG(CASE WHEN t.receipt_attached THEN 1 ELSE 0 END), 1) < 90
ORDER BY receipt_compliance_pct ASC

Question 3

What's our receipt rate?

SELECT ROUND(100 * AVG(CASE WHEN receipt_attached THEN 1 ELSE 0 END), 1) AS receipt_compliance_pct
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions
WHERE fiscal_year = 2026

Question 4

How many statements were late?

SELECT COUNT(*) AS late_statements
FROM `{{CATALOG}}`.`osa_pcard_review`.monthly_statements
WHERE (reconciled AND days_to_reconcile > 30)
   OR (NOT reconciled AND DATEDIFF(DATE'2026-06-30', statement_date) > 30)

Question 5

How many split purchases were there?

SELECT COUNT(*) AS split_purchase_groups FROM (
  SELECT t.card_id
  FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.cardholders c ON t.card_id = c.card_id
  GROUP BY t.card_id, t.merchant_name, t.transaction_date, c.single_purchase_limit
  HAVING COUNT(*) >= 2 AND MAX(t.amount) <= c.single_purchase_limit AND SUM(t.amount) > c.single_purchase_limit
)

Question 6

Who kept spending after they left?

SELECT c.card_id, c.cardholder_name, c.agency_code, c.termination_date,
       COUNT(*) AS purchases_after_termination, ROUND(SUM(t.amount), 2) AS total_after_termination
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.cardholders c ON t.card_id = c.card_id
WHERE c.termination_date IS NOT NULL AND t.transaction_date > c.termination_date
GROUP BY c.card_id, c.cardholder_name, c.agency_code, c.termination_date
ORDER BY total_after_termination DESC

Question 7

Total spend by department FY26

SELECT a.agency_name, ROUND(SUM(t.amount), 2) AS total_spend
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.agencies a ON t.agency_code = a.agency_code
WHERE t.fiscal_year = 2026
GROUP BY a.agency_name
ORDER BY total_spend DESC

Question 8

Which cards are dormant?

SELECT COUNT(*) AS dormant_cards
FROM `{{CATALOG}}`.`osa_pcard_review`.cardholders c
WHERE c.card_status = 'Active'
  AND NOT EXISTS (SELECT 1 FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t
                  WHERE t.card_id = c.card_id AND t.transaction_date > DATE'2026-04-01')

Question 9

Who are our big spenders?

SELECT c.card_id, c.cardholder_name, c.agency_code, ROUND(SUM(t.amount), 2) AS fy2026_spend
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.cardholders c ON t.card_id = c.card_id
WHERE t.fiscal_year = 2026
GROUP BY c.card_id, c.cardholder_name, c.agency_code
ORDER BY fy2026_spend DESC
LIMIT 10

Question 10

Purchases at places we don't allow this year

SELECT COUNT(*) AS blocked_purchases, ROUND(SUM(t.amount), 2) AS blocked_dollars
FROM `{{CATALOG}}`.`osa_pcard_review`.transactions t JOIN `{{CATALOG}}`.`osa_pcard_review`.merchant_categories m ON t.mcc = m.mcc
WHERE m.is_blocked AND t.fiscal_year = 2026

Fix 1: text instructions

  1. The data runs through June 30, 2026. Treat 2026-06-30 as today. "This year" means fiscal year 2026, and "last quarter" means fiscal year 2026 Q4 (April to June 2026).
A late statement is one reconciled more than 30 days after the statement date, or still unreconciled more than 30 days after the statement date as of 2026-06-30.
A dormant card is an Active card with no purchases from April 1 through June 30, 2026. Return a count unless the user asks for a list.
Bad receipt compliance means a receipt compliance rate below 90% for the fiscal year. Report compliance as a percentage rounded to one decimal.
Big spenders are the top 10 cardholders by total spend in fiscal year 2026.
"Places we don't allow" means blocked merchant categories. Return a count and total dollars unless the user asks for a list.

Fix 3: a metric view of your own

  1. CREATE OR REPLACE VIEW `{{CATALOG}}`.`{{SANDBOX}}`.pcard_metrics_{{NAME}}
WITH METRICS
LANGUAGE YAML
AS $$
  version: 1.1
  source: {{CATALOG}}.osa_pcard_review.transactions
  comment: "Official P-card metrics for OSA reviews. Data runs through June 30, 2026. Fiscal years run July 1 to June 30."
  joins:
    - name: agency
      source: {{CATALOG}}.osa_pcard_review.agencies
      on: source.agency_code = agency.agency_code
    - name: cardholder
      source: {{CATALOG}}.osa_pcard_review.cardholders
      on: source.card_id = cardholder.card_id
    - name: category
      source: {{CATALOG}}.osa_pcard_review.merchant_categories
      on: source.mcc = category.mcc
  dimensions:
    - name: Agency
      expr: agency.agency_name
      comment: "Agency that made the purchase"
      synonyms: ['department', 'dept', 'state agency']
    - name: Fiscal Year
      expr: source.fiscal_year
      comment: "NC fiscal year, named for the year it ends. FY26 and this year both mean 2026."
      synonyms: ['FY', 'year', 'this year']
    - name: Fiscal Quarter
      expr: source.fiscal_quarter
      comment: "Q1 = Jul-Sep, Q2 = Oct-Dec, Q3 = Jan-Mar, Q4 = Apr-Jun. Last quarter means FY2026 Q4."
      synonyms: ['quarter', 'last quarter']
    - name: Merchant Category Group
      expr: category.category_group
      comment: "Reporting group for the merchant category"
      synonyms: ['category', 'spend category']
    - name: Blocked Category
      expr: category.is_blocked
      comment: "True when card policy prohibits the merchant category"
      synonyms: ['not allowed', 'prohibited', "places we don't allow"]
  measures:
    - name: Total Spend
      expr: SUM(source.amount)
      comment: "Total P-card dollars spent"
      synonyms: ['spend', 'spending', 'dollars']
    - name: Purchase Count
      expr: COUNT(1)
      comment: "Number of P-card purchases"
      synonyms: ['transactions', 'purchases']
    - name: Receipt Compliance Rate
      expr: ROUND(100 * AVG(CASE WHEN source.receipt_attached THEN 1 ELSE 0 END), 1)
      comment: "Percent of purchases with a receipt attached. Low is bad."
      synonyms: ['receipt rate', 'receipt compliance', 'bad receipt compliance']
    - name: Purchases After Termination
      expr: COUNT(1) FILTER (WHERE cardholder.termination_date IS NOT NULL AND source.transaction_date > cardholder.termination_date)
      comment: "Purchases made after the cardholder left state employment"
      synonyms: ['spending after they left', 'terminated cardholder purchases']
$$

Worth knowing

Joins

Under Configure, Examples, Add, Joins, you can define how tables connect and the relationship type. Genie already joins these tables correctly, because the key columns share names across tables, so you don't need it today.

Genie Code suggestions

Now accept the suggestions you held back in section 2, and note which ones you'd keep in production. Re-running the benchmark tells you whether they helped.

Genie ontology

The shared context layer behind Genie. It combines modeled knowledge, such as metric views and domains, with knowledge Genie learns over time, and treats curated agents as authoritative. Your metric view is part of that modeled knowledge.

Trusted answers

When a user's question matches a parameterized example query, Genie runs that query and marks the answer as verified. It's the strongest signal you can give for questions that must always be answered the same way.

Troubleshooting & FAQ

The notebook says it can't find an agent ID

Paste the full URL of your agent from the browser address bar. The notebook pulls the 32-character ID out of it.

The notebook fails with a permission error

You need Can Edit or Can Manage on the agent. You get Can Manage automatically on agents you create, so check that the URL is for your own agent.

Creating the metric view fails

You need permission to create views in the schema you chose, and Select on the workshop tables. Check the schema name in your settings, or ask your Databricks workspace administrators which schema to use.

My score went down after a change

That's what benchmarks are for. Open the questions that changed, and check whether an instruction is contradicting an example query or the metric view. Remove one change at a time and re-run.

Benchmark details disappeared

Evaluation details are kept for about a week. Record your scores if you want to compare later.

Where do I find Genie Workbench?

It's a Databricks App, so look under Apps in the workspace. If it isn't there, your Databricks workspace administrators haven't deployed it yet. See the setup page.
