Measure it. Fix it.
Measure again.

A hands-on hour for OSA's technical team on making a Genie Agent reliable. You'll build an agent from a set of P-card tables, score it with a set of poorly worded questions written the way people really ask, fix what fails at the right layer, and re-run the benchmark to prove the fixes worked. Then you'll save the result as code.

Benchmarks

Questions with known right answers, so "it seems better" becomes a score you can track after every change.

Improvement layers

Instructions, example queries, metric views and agent-level metadata. Each fixes a different kind of failure.

Agents as code

A Declarative Automation Bundle captures the curated agent, benchmarks included, so it can be reviewed in Git and deployed again.

1 Kickoff

Goal: agree on what "good" means and how we'll measure it. 12:00 · 10 min

Users rarely ask the way a query is written. They use vague dates, shorthand only OSA would understand, and terms nobody has defined. Today's benchmark questions are poorly worded on purpose. A well-tuned agent should still get them right, and you'll treat each miss the way you'd treat a failing test.

Poorly worded: how people askWell worded: what they mean
Find fraud.Transactions made after the cardholder's termination date in fiscal year 2026.
Who are our big spenders?The top 10 cardholders by total spend in fiscal year 2026.
Which cards are dormant?Active cards with no purchases from April 1 to June 30, 2026.
How much did we spend last quarter?Total spend for fiscal year 2026 Q4, April to June 2026.

Business users were coached on the right-hand column last week. Your job is the other half: make the agent cope with the left-hand column, because that's how most people will ask.

Lower layers are more deterministic. Every piece of business logic should live as far down as possible.

Last option, least reliable

Text instructionsFast but optimistic

Text instructions: formatting, scope and clarification prompts. Great for fast iteration and subjective changes, but open to interpretation, and they can be ignored if the context gets overloaded.

SQL expressionsExample-based pattern matching for reliable outcomes

SQL expressions: Genie's strongest signal for writing queries. It learns from examples, which captures your team's expertise.

Unity Catalog metadataTable and column descriptions, synonyms, table context

Unity Catalog metadata: passive but important. It helps Genie pick the right tables and columns, and it helps everyone else who builds on Unity Catalog too.

Metric viewsEnforced semantic layer: calculations, joins, governed metrics

Metric views: enforced and deterministic. Calculations always run exactly as defined. You can add synonyms for KPIs, so Genie learns your business terms.

Preferred, most reliable

Today's flow

  1. Create a bare agent from the six tables, load 10 benchmark questions, and run a baseline.
  2. Curate it: instructions, a metric view, example queries and a glossary.
  3. Re-run the benchmark, accept the fixes Genie proposes, and re-run again.
  4. Save the curated agent as a bundle and deploy it.
How a benchmark scores. For each question, Genie answers as it would for a user, and its answer is compared with a reference answer. The run reports an accuracy score, and you can open any question to see why it passed or failed.

The 10 benchmark questions

The SQL uses the catalog from your settings. Each reference answer was checked against the workshop tables.

Question 1

How much did we spend last quarter?

SELECT ROUND(SUM(amount), 2) AS total_spend
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions
WHERE fiscal_year = 2026 AND fiscal_quarter = 'Q4'

Question 2

Which agencies have bad receipt compliance?

SELECT a.agency_name,
       ROUND(100 * AVG(CASE WHEN t.receipt_attached THEN 1 ELSE 0 END), 1) AS receipt_compliance_pct
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.agencies a ON t.agency_code = a.agency_code
WHERE t.fiscal_year = 2026
GROUP BY a.agency_name
HAVING ROUND(100 * AVG(CASE WHEN t.receipt_attached THEN 1 ELSE 0 END), 1) < 90

Question 3

What's our receipt rate?

SELECT ROUND(100 * AVG(CASE WHEN receipt_attached THEN 1 ELSE 0 END), 1) AS receipt_compliance_pct
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions
WHERE fiscal_year = 2026

Question 4

How many statements were late?

SELECT COUNT(*) AS late_statements
FROM `{{CATALOG}}`.`{{SCHEMA}}`.monthly_statements
WHERE (reconciled AND days_to_reconcile > 30)
   OR (NOT reconciled AND DATEDIFF(DATE'2026-06-30', statement_date) > 30)

Question 5

How many split purchases were there?

SELECT COUNT(*) AS split_purchase_groups FROM (
  SELECT t.card_id
  FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c ON t.card_id = c.card_id
  WHERE t.fiscal_year = 2026
  GROUP BY t.card_id, t.merchant_name, t.transaction_date, c.single_purchase_limit
  HAVING COUNT(*) >= 2 AND MAX(t.amount) <= c.single_purchase_limit AND SUM(t.amount) > c.single_purchase_limit
)

Question 6

Who kept spending after they left?

SELECT c.cardholder_name,
       COUNT(*) AS purchases_after_termination, ROUND(SUM(t.amount), 2) AS total_after_termination
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c ON t.card_id = c.card_id
WHERE c.termination_date IS NOT NULL AND t.transaction_date > c.termination_date AND t.fiscal_year = 2026
GROUP BY c.card_id, c.cardholder_name

Question 7

Total spend by department FY26

SELECT a.agency_name, ROUND(SUM(t.amount), 2) AS total_spend
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.agencies a ON t.agency_code = a.agency_code
WHERE t.fiscal_year = 2026
GROUP BY a.agency_name

Question 8

Which cards are dormant?

SELECT c.card_id, c.cardholder_name
FROM `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c
WHERE c.card_status = 'Active'
  AND NOT EXISTS (SELECT 1 FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t
                  WHERE t.card_id = c.card_id AND t.transaction_date > DATE'2026-04-01')

Question 9

Who are our big spenders?

SELECT c.cardholder_name, ROUND(SUM(t.amount), 2) AS fy2026_spend
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c ON t.card_id = c.card_id
WHERE t.fiscal_year = 2026
GROUP BY c.card_id, c.cardholder_name
ORDER BY fy2026_spend DESC
LIMIT 10

Question 10

Purchases at places we don't allow this year

SELECT COUNT(*) AS blocked_purchases, ROUND(SUM(t.amount), 2) AS blocked_dollars
FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t JOIN `{{CATALOG}}`.`{{SCHEMA}}`.merchant_categories m ON t.mcc = m.mcc
WHERE m.is_blocked AND t.fiscal_year = 2026

Run the baseline

Expect to start low. A bare agent only knows the tables. The goal for today is to get above 80%.

3 Curate the agent

Goal: teach the agent OSA's definitions, putting each one at the most reliable layer that works. 12:20 · 15 min

Step 1: instructions

  1. The data runs through June 30, 2026. Treat 2026-06-30 as today. "Last quarter" means fiscal year 2026 Q4 (April to June 2026).
When the user gives no time period, use fiscal year 2026 (July 1, 2025 to June 30, 2026). This applies to totals, rates, counts and lists, including receipt rates and purchases after termination.
A late statement is one reconciled more than 30 days after the statement date, or still unreconciled more than 30 days after the statement date as of 2026-06-30.
A dormant card is an Active card with no purchases from April 1 through June 30, 2026. List the cards; give a count only if the user asks how many.
Bad receipt compliance means a receipt compliance rate below 90% for the fiscal year. 
Big spenders are the top 10 cardholders by total spend in the period. Show the cardholder name and their spend.
Cardholder names are not unique. When ranking or totaling by cardholder, group by card_id and show the cardholder name.
For questions about purchases at places we don't allow (blocked merchant categories), return the number of purchases and the total dollars, not a list, unless the user asks for a list.
Round percentages to one decimal place and dollar amounts to two decimal places.
A split purchase is two or more purchases on the same card, at the same merchant, on the same day, where each purchase is at or under the card's single-purchase limit but together they exceed it. Count each card, merchant and day group once.
Another option: Generate with Genie. The Generate with Genie button (Improve with Genie once there's text) profiles the tables, reads your benchmark questions and examples, and drafts instructions from what it finds, including the data's date range and fiscal calendar. It takes a few minutes, so we'll paste ours today. Try it afterward and compare its draft with these definitions.

Step 2: a metric view of your own

  1. CREATE OR REPLACE VIEW `{{CATALOG}}`.`{{SANDBOX}}`.pcard_metrics_{{NAME}}
WITH METRICS
LANGUAGE YAML
AS $$
  version: 1.1
  source: {{CATALOG}}.`{{SCHEMA}}`.transactions
  comment: "Official P-card metrics for OSA reviews. Data runs through June 30, 2026. Fiscal years run July 1 to June 30."
  joins:
    - name: agency
      source: {{CATALOG}}.`{{SCHEMA}}`.agencies
      on: source.agency_code = agency.agency_code
    - name: cardholder
      source: {{CATALOG}}.`{{SCHEMA}}`.cardholders
      on: source.card_id = cardholder.card_id
    - name: category
      source: {{CATALOG}}.`{{SCHEMA}}`.merchant_categories
      on: source.mcc = category.mcc
  dimensions:
    - name: Agency
      expr: agency.agency_name
      comment: "Agency that made the purchase"
      synonyms: ['department', 'dept', 'state agency']
    - name: Fiscal Year
      expr: source.fiscal_year
      comment: "NC fiscal year, named for the year it ends. FY26 and this year both mean 2026."
      synonyms: ['FY', 'year', 'this year']
    - name: Fiscal Quarter
      expr: source.fiscal_quarter
      comment: "Q1 = Jul-Sep, Q2 = Oct-Dec, Q3 = Jan-Mar, Q4 = Apr-Jun. Last quarter means FY2026 Q4."
      synonyms: ['quarter', 'last quarter']
    - name: Merchant Category Group
      expr: category.category_group
      comment: "Reporting group for the merchant category"
      synonyms: ['category', 'spend category']
    - name: Blocked Category
      expr: category.is_blocked
      comment: "True when card policy prohibits the merchant category"
      synonyms: ['not allowed', 'prohibited', "places we don't allow"]
  measures:
    - name: Total Spend
      expr: SUM(source.amount)
      comment: "Total P-card dollars spent"
      synonyms: ['spend', 'spending', 'dollars']
    - name: Purchase Count
      expr: COUNT(1)
      comment: "Number of P-card purchases"
      synonyms: ['transactions', 'purchases']
    - name: Receipt Compliance Rate
      expr: ROUND(100 * AVG(CASE WHEN source.receipt_attached THEN 1 ELSE 0 END), 1)
      comment: "Percent of purchases with a receipt attached. Low is bad."
      synonyms: ['receipt rate', 'receipt compliance', 'bad receipt compliance']
    - name: Purchases After Termination
      expr: COUNT(1) FILTER (WHERE cardholder.termination_date IS NOT NULL AND source.transaction_date > cardholder.termination_date)
      comment: "Purchases made after the cardholder left state employment"
      synonyms: ['spending after they left', 'terminated cardholder purchases']
$$

Step 3: example queries

Usage guidance tells Genie when to use an example. A question that matches an example gets that exact SQL, which makes the answer repeatable.

  1. How many statements were late?

    SELECT COUNT(*) AS late_statements
FROM `{{CATALOG}}`.`{{SCHEMA}}`.monthly_statements
WHERE (reconciled AND days_to_reconcile > 30)
   OR (NOT reconciled AND DATEDIFF(:as_of_date, statement_date) > 30)

  2. The date to measure lateness from. The workshop data runs through 2026-06-30, so use that unless the user gives another date.

  3. Use for questions about late, overdue or unreconciled statements. A statement is late if it was reconciled more than 30 days after the statement date, or is still unreconciled more than 30 days after it.

  4. Which cards are dormant?

    SELECT c.card_id, c.cardholder_name, a.agency_name
FROM `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c
JOIN `{{CATALOG}}`.`{{SCHEMA}}`.agencies a ON c.agency_code = a.agency_code
WHERE c.card_status = 'Active'
  AND NOT EXISTS (SELECT 1 FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t
                  WHERE t.card_id = c.card_id AND t.transaction_date > DATE'2026-04-01')

    Usage guidance:

    Use for questions about dormant, inactive or unused cards. A dormant card is an Active card with no purchases from April 1 through June 30, 2026. List the cards; give a count only if the user asks how many.

  5. How many split purchases were there in fiscal year 2026?

    SELECT COUNT(*) AS split_purchase_groups FROM (
  SELECT t.card_id, t.merchant_name, t.transaction_date
  FROM `{{CATALOG}}`.`{{SCHEMA}}`.transactions t
  JOIN `{{CATALOG}}`.`{{SCHEMA}}`.cardholders c ON t.card_id = c.card_id
  WHERE t.fiscal_year = 2026
  GROUP BY t.card_id, t.merchant_name, t.transaction_date, c.single_purchase_limit
  HAVING COUNT(*) >= 2 AND MAX(t.amount) <= c.single_purchase_limit AND SUM(t.amount) > c.single_purchase_limit
)

    Usage guidance:

    Use for questions about split purchases: purchases broken up to stay under a card's single-purchase limit. Count each card, merchant and day group once. Change the fiscal year filter to match the question, and default to fiscal year 2026.

Changes made in the agent apply only to your agent, so they're safe on shared tables. Pages belong to a domain and are shared with everyone who can see it once published.

Worth knowing

Joins

Under Configure, Examples, Add, Joins, you can define how tables connect and the relationship type. Genie already joins these tables correctly, because the key columns share names across tables, so you don't need it today.

Genie Code suggestions

The suggestions you held back in section 2 are still available. Accept the ones you'd keep in production, and the re-run will tell you whether they helped.

Genie ontology

The shared context layer behind Genie. It combines modeled knowledge, such as metric views and domains, with knowledge Genie learns over time, and treats curated agents as authoritative. Your metric view is part of that modeled knowledge.

Trusted answers

When a user's question matches a parameterized example query, Genie runs that query and marks the answer as verified. It's the strongest signal you can give for questions that must always be answered the same way.

5 Keep it as code

Goal: save the curated agent as a Declarative Automation Bundle, so it can be reviewed in Git and deployed again. 12:45 · 15 min

The bundle holds everything you built: the tables, instructions, example queries, synonyms, accepted fixes and all 10 benchmark questions. You'll do it from the workspace, with one command in the web terminal to pull the agent in.

  2. # Starter configuration for the NC OSA Genie workshop bundle.
# Next step: databricks bundle generate genie-space --existing-id <agent ID> --key pcard_review
bundle:
  name: osa-pcard-genie
  engine: direct # Genie agents need the direct deployment engine

include:
  - resources/*.yml

targets:
  dev:
    mode: development
    default: true

  prod:
    workspace:
      root_path: /Workspace/Users/${workspace.current_user.userName}/.bundle/${bundle.name}/prod
    resources:
      genie_spaces:
        pcard_review:
          title: "P-Card Review (Production)"
          # Uncomment and set the auditors' group before sharing:
          # permissions:
          #   - level: CAN_RUN
          #     group_name: <auditors group>
  3. cd /Workspace/Users/<you>/<your Git folder>/osa-pcard-genie
databricks bundle generate genie-space --existing-id {{AGENT_ID}} --key pcard_review

    This adds resources/pcard_review.genie_space.yml and src/pcard_review.geniespace.json. Open the JSON in the editor: that's your curated agent as code.

Making changes from here on

Edit your own agent in the UI and re-run its benchmarks. Then run the command below in the web terminal to pull the changes into the bundle, review the diff in the Git folder, commit, and deploy prod again from the Deployments pane.

databricks bundle generate genie-space --resource pcard_review --force
Before sharing the production copy, uncomment the permissions block in databricks.yml and set the auditors' group, so access is part of the code too. Deploying to another workspace is done with the CLI from a CI/CD pipeline, not from the workspace UI.

Genie Workbench

Genie Workbench is a Databricks App that does much of this automatically. It gives an agent a quick quality score with recommendations, and its Auto-Optimize job tries changes against your benchmarks and keeps the ones that raise the score. The job runs in the background, so it suits overnight tuning rather than a live session.

Cheat sheet

Where things are

  • New agent: Genie Agents, New.
  • Benchmarks: Benchmark at the top of the agent, then the Questions tab and Run all benchmarks.
  • Results: Benchmark, then the Evaluations tab.
  • Instructions: Configure, Instructions, then Generate with Genie or Improve with Genie.
  • Example queries: Configure, Examples, Add, then Parameters and Usage Guidance.
  • Add a metric view: Configure, Data, Add.
  • Agent-level descriptions and synonyms: Configure, Sources, pencil on a column.
  • Proposed fixes: a failed question in Evaluations, then Review proposed fixes.
  • Glossary Pages: Discover, Pages, Create page.
  • Bundle: a Git folder, Create, Bundle. Deploy from the Deployments pane.

Habits

  • Measure before you change anything.
  • One fix at a time, then re-run.
  • Fix it at the lowest layer that works.
  • Two phrasings of every important question.
  • A failing benchmark can be the benchmark's fault.

Troubleshooting & FAQ

The notebook says it can't find an agent ID

Paste the full URL of your agent from the browser address bar. The notebook pulls the 32-character ID out of it.

The notebook fails with a permission error

You need Can Edit or Can Manage on the agent. You get Can Manage automatically on agents you create, so check that the URL is for your own agent.

Creating the metric view fails

You need permission to create views in the schema you chose, and Select on the workshop tables. Check the schema name in your settings, or ask your Databricks workspace administrators which schema to use.

My score went down after a change

That's what benchmarks are for. Open the questions that changed, and check whether an instruction is contradicting an example query or the metric view. Remove one change at a time and re-run.

Benchmark details disappeared

Evaluation details are kept for about a week. Record your scores if you want to compare later.

Where do I find Genie Workbench?

It's a Databricks App, so look under Apps in the workspace. If it isn't there, ask your Databricks workspace administrators.
